# 📄 PRD: Прототип передачи текста с ПК через ESP32 в VR/AR шлем

**Дата:** 24 августа 2026 г.
**Статус:** Черновик / Инициация
**Цель проекта:** Подтвердить жизнеспособность связки `ПК (COM) -> ESP32 (BLE) -> VR Шлем (AR/Passthrough)` для отображения динамического текста в поле зрения пользователя.

---

## 1. Архитектура и поток данных (Data Flow)
Система состоит из трех узлов. Данные движутся строго в одном направлении:

1. **Узел 1: ПК (Источник).** Скрипт или приложение отправляет строку текста в виртуальный или физический COM-порт.
2. **Узел 2: ESP32 (Транслятор).** Принимает данные по UART (COM-порт), парсит их и обновляет значение в BLE GATT Characteristic.
3. **Узел 3: VR Шлем (Приемник и Рендер).** VR-приложение (работающее в режиме Mixed Reality / Passthrough) сканирует BLE, подключается к ESP32, считывает обновленный текст и рендерит 3D-надпись перед пользователем.

---

## 2. Требования к оборудованию (Hardware)
* **Микроконтроллер:** ESP32 (с поддержкой Bluetooth 4.2/5.0 BLE).
* **VR Шлем:** Meta Quest 2/3/Pro или Pico 4 (устройства на базе Android с поддержкой Color Passthrough / Mixed Reality). *Примечание: Для PCVR шлемов (типа Valve Index) архитектура будет другой, данный PRD написан для автономных Android-шлемов.*
* **ПК:** Любая ОС (Windows/macOS/Linux) с доступом к USB/COM порту.
* **Кабель:** USB для подключения ESP32 к ПК.

---

## 3. Требования к программному обеспечению (Software Stack)

### 3.1. ПК (Отправитель)
* **Язык:** Python (рекомендуется для прототипа) или C#.
* **Библиотеки:** `pyserial` (Python) или `System.IO.Ports` (C#).
* **Функционал:** Простой консольный или GUI интерфейс для ввода текста и отправки его в COM-порт с добавлением символа конца строки (`\n`).

### 3.2. ESP32 (Прошивка)
* **Среда разработки:** Arduino IDE или PlatformIO.
* **Библиотеки:** `BLEDevice`, `BLEServer`, `BLE2902` (стандартные Arduino BLE библиотеки для ESP32).
* **Роль в BLE:** **Peripheral (Server)**. ESP32 создает BLE сервис и характеристику, отдает данные по подписке (Notify).
* **Функционал:**
  * Инициализация Serial (например, `Serial.begin(115200)`).
  * Инициализация BLE Server с уникальными UUID (Service UUID, Characteristic UUID).
  * Чтение буфера Serial. При получении полного пакета (до `\n`) — обновление значения Characteristic и отправка `pCharacteristic->notify()`.

### 3.3. VR Шлем (Приложение)
* **Движок:** Unity 3D (или Unreal Engine).
* **SDK:** Meta XR SDK (для доступа к Passthrough / Mixed Reality) или OpenXR.
* **BLE Плагин:** Так как Unity не имеет встроенного BLE Client для Android, потребуется плагин (например, *BluetoothLE for Unity* от CloudM2, *Unity BLE Plugin* или написание нативного Android AAR wrapper'а).
* **Роль в BLE:** **Central (Client)**.
* **Функционал:**
  * Сканирование BLE устройств по имени или MAC-адресу ESP32.
  * Подключение и подписка на Notify Characteristic.
  * Рендеринг текста (используя `TextMeshPro` в 3D пространстве).
  * Активация режима Passthrough (AR).

## 4. Функциональные требования (Functional Requirements)

| ID | Функция | Описание | Приоритет |
|---|---|---|---|
| FR-1 | Отправка с ПК | ПК отправляет текст. Поддерживаются только ASCII/UTF-8 символы. | Must Have |
| FR-2 | Обработка на ESP32 | ESP32 принимает текст, игнорирует мусор, ждет символ `\n` для подтверждения конца сообщения. | Must Have |
| FR-3 | BLE Трансляция | ESP32 обновляет BLE характеристику и триггерит уведомление (Notification) для подписанных клиентов. | Must Have |
| FR-4 | AR Рендеринг | VR приложение включает камеру (Passthrough) и размещает 3D текст на фиксированном расстоянии (например, 1.5 метра) перед камерой шлема. | Must Have |
| FR-5 | Авто-переподключение | Если связь BLE теряется, VR приложение должно пытаться переподключиться. ESP32 должен продолжать рекламировать себя (Advertising). | Should Have |
| FR-6 | Очистка текста | Если с ПК отправлена пустая строка или спец. команда (например, `CLR`), надпись в VR должна скрываться. | Nice to Have |

---

## 5. Нефункциональные требования (Non-Functional)
* **Задержка (Latency):** Время от нажатия "Enter" на ПК до появления текста в шлеме не должно превышать **300-500 мс** (с учетом BLE интервалов и рендеринга).
* **Дальность:** Стабильная работа на расстоянии до **3-5 метров** (в пределах комнаты).
* **Энергопотребление:** ESP32 должна работать от USB-питания ПК (режимы сна не требуются для прототипа).
* **Безопасность:** Шифрование BLE не требуется (прототип).

## 6. Риски и пути их решения (Risks & Mitigations)

| Риск | Вероятность | Влияние | Митигация (Решение) |
|---|---|---|---|
| **Проблемы с BLE в Unity на Android** | Высокая | Критическое | Использовать проверенные платные/бесплатные ассеты из Unity Asset Store или писать нативный Java-код для Android с вызовом через JNI. |
| **Разрыв BLE соединения** | Средняя | Среднее | Настроить ESP32 на агрессивный Advertising interval (например, 20-50мс). В Unity сделать таймаут и перезапуск сканирования. |
| **Блокировка COM порта** | Средняя | Среднее | Читать COM-порт в отдельном потоке (Thread) или использовать асинхронные методы (`ReadLineAsync`), чтобы не фризить UI на ПК. |
| **Ограничения Passthrough API** | Низкая | Среднее | Убедиться, что используется актуальная версия Meta XR SDK и в манифесте Android (`AndroidManifest.xml`) прописаны разрешения на камеру (`android.permission.CAMERA`). |

## 7. Критерии приемки (Acceptance Criteria / Definition of Done)
Прототип считается успешно протестированным, если:
1. [ ] На ПК вводится текст "Hello VR", он успешно доходит по COM-порту до ESP32.
2. [ ] ESP32 успешно поднимает BLE Server и отдает текст "Hello VR" по воздуху.
3. [ ] VR Шлем подключается к ESP32 без использования смартфона (напрямую).
4. [ ] В VR шлеме включается режим дополненной реальности (Passthrough).
5. [ ] Перед глазами пользователя появляется 3D-надпись "Hello VR".
6. [ ] При вводе нового текста на ПК надпись в шлеме обновляется без перезапуска приложений.

## 8. План действий (Next Steps для разработчика)

**Шаг 1: "Железо и ESP32" (День 1)**
* Написать скетч для ESP32: чтение Serial, вывод в Serial Monitor (для отладки) и создание простейшего BLE Server (можно использовать стандартный пример `BLE_notify` из библиотек ESP32, заменив в нем счетчик на чтение Serial).
* Написать Python-скрипт для отправки строк в COM-порт. Проверить связку ПК <-> ESP32 через любой BLE-сниффер или приложение на смартфоне (например, *nRF Connect*).

**Шаг 2: "VR Приложение и BLE" (День 2-3)**
* Создать пустой проект в Unity. Настроить Meta XR SDK.
* Подключить BLE плагин. Написать скрипт, который ищет ESP32 по имени, подключается и читает строку.
* Вывести полученную строку в обычный UI (Canvas), чтобы убедиться, что данные доходят.

**Шаг 3: "AR и Интеграция" (День 4)**
* Заменить обычный UI на 3D TextMeshPro.
* Настроить привязку текста к камере (чтобы он всегда был перед глазами) или к точке в пространстве (World-locked).
* Включить Passthrough (Mixed Reality).
* Провести финальные тесты, замерить задержку, устранить баги.

---
*Совет: На этапе настройки BLE в Unity, обязательно протестируйте UUID сервиса и характеристики на ESP32 и в Unity — они должны **идеально совпадать**, иначе шлем не увидит данные.*
